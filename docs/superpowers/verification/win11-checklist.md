## 关卡 0：冒烟（不过就停，下面全部无意义）

历史教训：之前几轮验证都假设「终端已经能用」，然后在这个假设上验证配色、
验证流控——而实际上连提示符都没出来。所以先过这一关。

**准备**：Actions 下载 `hackerterm-windows-x64` → 解压到**下载文件夹之外**
（例如 `D:\ht\`，理由见关卡 4）→ 运行里面的 `HackerTerm.exe`。

| # | 操作 | 通过标准 | 不过说明什么 |
|---|---|---|---|
| 0.1 | 启动，等窗口出现 | 上方是日志区，**下方一大片是终端**，终端占满窗口剩余高度 | 终端区仍是顶部一个小框 → xterm.css 没生效/没打进包 |
| 0.2 | 看终端里有没有 PowerShell 横幅和 `PS C:\...>` 提示符 | 有 | 无横幅 → 数据面没通；有横幅无提示符 → PTY 起了但 shell 没就绪 |
| 0.3 | **敲英文** `echo hello` 回车 | 字符**边敲边出现在提示符后**，回车后下一行显示 `hello` | 字符不出现 → helper-textarea 定位仍不对（CSS）；字符出现但无回显 → 回程数据面断 |
| 0.4 | 敲中文（微软拼音）`你好` 上屏 | 候选框跟着光标走，上屏后终端里是 `你好` | 候选框跑到窗口左上角 → IME 定位问题，记进关卡 3 |
| 0.5 | 缩放窗口大小 | 终端跟着重排，**日志区高度不变**、终端吃掉全部剩余空间 | 终端不重排 → FitAddon 没接上 resize |

**0.1 / 0.3 任一不过：停下来，把日志区全文回报，不要往下跑。**

### 4.5 启动耗时定位（97 秒问题）

日志区顶部现在有一条完整时间线。**把这几行原样回报**：

```
main:module_load / main:app_whenReady / main:fork_call / main:core_spawn
core-host:module_start / core-host:ht_node_import_start / ht_node_import_end
main:create_window_call / main:did_finish_load
```

看**相邻两个时间戳之间哪一段有几十秒的空档**，那一段就是元凶。
头号嫌疑是 `ht_node_import_start → ht_node_import_end`（原生 .node 模块
加载 + Defender 实时扫描）。

配套两个零成本对照实验，各花 30 秒：

| # | 实验 | 若变快说明 |
|---|---|---|
| 4.5a | **同一个包再启动第二次** | 首次扫描/预热成本，第二次走缓存 |
| 4.5b | 把解压目录**移出下载文件夹**再跑 | Mark-of-the-Web：从网上下的文件带标记，Defender 对它更凶 |

## 本轮跑不了的项（不要假装验证过）

| 原清单项 | 缺什么 | 归属 |
|---|---|---|
| CMD / WSL / Git Bash 起会话 | `boot.ts` 里 `shell: ''` 写死，无 shell 选择 UI，协议字段倒是有 | M1 |
| Tab 崩溃隔离（原 T9 Step 3 第 1–4 项） | **只有一个 BrowserWindow，根本没有 Tab**。「一 Tab 一进程」还没有载体 | M1，且需先定方案（多 BrowserWindow vs 其他） |
| 「点击重开」恢复会话 | 无此 UI，无重连逻辑 | M1 |
| 杀掉 core utility process 后自动重启 | `main/index.ts` 的 `utilityProcess.fork` **没有 `on('exit')` 处理**，不会重启 | M1 |
| 连字字体渲染（xterm #3303） | 当前字体 Consolas 无连字，要换成 Fira Code 一类才谈得上 | M1（随字体配置一起） |
| macOS 全部项 | 还没出 mac 包 | M1 |

**唯一半个能跑的**：手动杀掉 core utility process，观察主进程不跟着崩、窗口还在。
但「自动重启核心」不会发生，这是已知缺口，不算失败。
