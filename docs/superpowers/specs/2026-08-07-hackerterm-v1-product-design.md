# HackerTerm V1 产品设计

> 状态：草案，待评审 · 日期：2026-08-07
> **本文只描述产品：用户看到什么、能做什么、我们承诺什么。不含任何技术实现。**

---

# 第一部分 · 产品定义

## 1. 定位

> **把「连上去」「看明白」「改下去」收进一个窗口，并让 AI 同时看得见这三件事。**

不是更快的终端，不是更好的数据库客户端。
是**唯一一个终端和数据库共用同一条连接、同一条隧道、同一份 AI 上下文的工具**。

## 2. 目标用户

| | 画像 | 现在用什么 | 痛点 |
|---|---|---|---|
| **主要** | 后端 / 全栈开发者 | iTerm2/Windows Terminal + Navicat + 一堆窗口 | 上下文在多个工具间反复搬运 |
| **主要** | 运维 / DBA | Xshell / FinalShell + Navicat | 连接信息各处重复维护，生产误操作风险 |
| **次要（V2 付费方）** | 企业技术负责人 | 无统一方案 | 账号密码散落个人电脑，无审计，人走了账号还在 |

## 3. 核心场景（产品要跑通的那条线）

> 小李收到告警。他打开 HackerTerm，在左侧点 `web-01` —— 终端连上了。
> 日志里报 `Duplicate entry for key 'uk_order_no'`。
> 他按 `Ctrl+L` 问 AI 这是什么，AI 已经看到了这段报错。
> AI 说是 `orders` 表的唯一索引冲突。他在左侧 `web-01` 下面直接点 `orders_db`
> —— **不用再填一遍连接、不用再配一遍跳板**，因为它就挂在这台机器下面。
> DB 面板打开，AI 顺手给出了排查用的 SQL。他执行、看到重复数据、确认、提交。
> **全程一个窗口，没切过应用，没重复输入过任何连接信息。**

这条线跑不通，产品就不成立。V1 的所有取舍都服务于这条线。

## 4. 明确不做（V1）

| 不做 | 理由 |
|---|---|
| 超过 2 种数据库 | DBeaver 支持 80+ 种，广度赛道已死 |
| ER 图 / 报表 / 数据同步 / 备份还原 | Navicat 的地盘，与核心场景无关 |
| 插件市场（评分/下载/更新） | V1 只留接口，生态是 V2+ 的事 |
| 配置云同步 | 需要账号体系和服务端，是独立项目 |
| 移动端 / Web 端 | 分散精力 |
| 会话录制回放 / SQL 审批流 | V2 企业版 |

# 第二部分 · 信息架构

## 5. 三个核心概念

```
连接 (Connection)          ← 用户维护的唯一资产
  └─ 会话 (Session)         ← 一个连接可以开多个会话
       └─ 面板 (Panel)      ← 终端 / 文件 / 日志 / 数据库 / AI
```

**「连接」是产品的中心。** 用户一辈子只维护连接，其它都是从连接派生的。
这一条决定了：文件管理、日志、数据库**都不是顶层功能**，它们是连接的子能力。

## 6. 主界面

```
┌──────────────────┬──────────────────────────────────────────────┐
│ 🔍 搜索连接       │  ~/proj ×  │  web-01 ×  │ orders_db × │ + │🤖│
│                  ├──────────────────────────────────────────────┤
│ ▼ 最近            │ ~/proj $ cargo build                         │
│   ● web-01   2m  │    Compiling hackerterm v0.1.0               │
│   ○ orders_db    │ error[E0308]: mismatched types               │
│                  │   --> src/main.rs:42:9                       │
│ ▼ 生产环境 🔒     │                                              │
│   ● web-01       │ ~/proj $ █                                   │
│     ├ 📁 文件     │                                              │
│     ├ 📄 日志     │                                              │
│     └ 🗄 orders_db│                                              │
│   ○ web-02       │                                              │
│                  │                                              │
│ ▼ 本地            │                                              │
│   🖥 zsh          │                                              │
│   🗄 dev_mysql    │                                              │
│                  ├──────────────────────────────────────────────┤
│ ＋ 新建连接       │ 🤖 构建失败 · Ctrl+K 分析 · Ctrl+L 打开 AI    │
└──────────────────┴──────────────────────────────────────────────┘
     侧栏                        Tab 区
   Ctrl+B 收起                可任意 Split
```

### 为什么侧栏可折叠

| 收起时 | 展开时 |
|---|---|
| 纯终端，零干扰 | 连接树，Xshell 体验 |
| toC 开发者的默认状态 | toB 运维的默认状态 |

**更重要的原因**：V2 企业版下发的连接必须有落点。带 🔒 的分组就是企业下发的，
用户不可删改。V1 如果做成纯终端形态，V2 要凭空长出一棵树，那是信息架构重做。

### 侧栏节点

| 图标 | 含义 | 双击 |
|---|---|---|
| 🖥 | 本地 Shell | 开终端 Tab |
| ● ◐ ○ ⊗ | SSH 主机（已连 / 连接中 / 未连 / 失败） | 开终端 Tab 并连接 |
| 📁 | 文件（SSH 主机的子项） | 开文件面板 |
| 📄 | 日志（SSH 主机的子项） | 开日志面板 |
| 🗄 | 数据库 | 开数据库 Tab |
| 🔒 | 企业下发分组（V2） | 只读 |

# 第三部分 · 功能模块

> 每个模块统一按：**是什么 → 用户看到什么 → 关键交互 → V1 不做** 描述。

## 7. 终端

**是什么**　产品的地基，必须做到和市面最好的终端同级，不能有明显短板。

**用户看到什么**
- Tab + 任意方向 Split（可嵌套），拖拽调整比例
- 真彩色（1600 万色）、粗体/斜体/下划线、连字、Emoji
- **中文等宽对齐正确**（很多终端做不好，中文用户一眼就能看出来）
- 无限回滚，滚多久都不卡
- 链接可 Ctrl+点击打开
- 新开 Tab 自动继承当前目录

**关键交互**
- 粘贴多行时**先弹确认**，显示将要执行的内容 —— 防止误粘贴直接执行
- 搜索（`Ctrl+F`）支持正则，命中项在滚动条上标出位置
- 选中即复制（可关），右键粘贴（可配）

**"丝滑"的可验收定义**（这是产品承诺，不是形容词）

| 指标 | 承诺 |
|---|---|
| 冷启动到可输入 | **< 300 ms** |
| 按键到显示 | **< 16 ms**（一帧内） |
| 刷大量日志 | 不掉帧、不卡界面 |
| 高刷屏 | 跟随屏幕刷新率（120Hz 就跑 120Hz） |
| 拖动窗口改大小 | 内容实时重排，不白屏 |
| **无输出时 CPU 占用** | **0%** |

最后一条最容易被做砸：无脑每帧重绘会让笔记本风扇狂转。
**没有内容变化就不重绘，是硬性要求。**

**V1 不做**　在终端里直接显示图片、终端内置的多窗口复用（tmux 那类）。

---

## 8. 自动补全 —— V1 最核心的差异化

**是什么**　让终端有 IDE 级的补全。这是 toC 用户"用了就回不去"的唯一功能。

**用户看到什么**

```
你输入： git ch▌

行内直接显示灰字：  git ch|eckout          ← 按 → 接受，不用看列表

按 Tab 展开完整列表：
   ┌──────────────────────────────────────────────┐
   │ ▸ git checkout          切换分支      ⭐常用  │
   │   git cherry-pick       拣选提交              │
   │   git check-ignore      调试 gitignore        │
   │ ────────────────────────────────────────────  │
   │ ▸ git checkout feature/auth-fix        (分支) │
   │ ▸ git checkout -b fix/E0308-mismatched   🤖   │
   └──────────────────────────────────────────────┘
```

**三层来源**

| 层 | 提供什么 | 举例 |
|---|---|---|
| **① 命令知识** | 命令、子命令、参数、说明 | `git checkout` 是什么意思 |
| **② 你的习惯** | 按「用得多 + 用得近 + 当前目录 + 当前主机」排序 | 你在这个项目最常 checkout 哪个分支 |
| **③ AI** | 结合当前上下文猜你要干什么 | 刚才报错 E0308 → 建议开修复分支 |

**关键交互（决定它是神器还是烦人）**

1. **永不卡输入。** ①② 立刻出，③ 慢慢来。
2. **AI 建议只能追加到列表末尾，绝不重排已显示的项。**
   异步内容插进来导致误选，是同类产品最大的抱怨来源。
3. **默认不弹窗。** 只显示一条行内灰字，按 `Tab` 才展开列表。
4. **SSH 到服务器上照样补全，且不需要在服务器上安装任何东西。**
   这是竞品普遍做不好的地方，是我们的机会点。
5. **数据库 Tab 里补全的是表名、列名、JOIN 条件。** 同一套交互，换个内容源。

**V1 不做**　补全内容的用户自定义编辑器（先用内置的）。

## 9. SSH 与连接管理

**是什么**　用户唯一需要维护的资产，产品的中心。

**用户看到什么** —— 新建连接表单

| 分组 | 字段 |
|---|---|
| 基础 | 名称、分组、Host、Port、User、备注、**标签颜色** |
| 认证 | 密码 / 私钥（含口令）/ ssh-agent / 键盘交互 |
| 跳板 | 多级跳板，**直接选已有连接作为跳板**，可链式 |
| 隧道 | 本地转发 / 远程转发 / 动态代理，可配多条 |
| 会话 | 登录后自动执行的命令、编码、保活、断线自动重连 |
| 外观 | **该连接专属主题**（生产环境标红） |

**关键交互**

- **一键导入**：`~/.ssh/config`、Xshell、FinalShell、PuTTY、MobaXterm 会话。
  *迁移成本是国内用户换工具的第一障碍，这一项的优先级高于很多新功能。*
- **生产环境防误操作**
  - 标记为「生产」的连接 → 整个 Tab 变红，标题带 ⚠
  - 在生产 Tab 里敲 `rm -rf` / `DROP` / `TRUNCATE` / `shutdown` / `kill -9`，
    **回车前弹确认**，显示完整解析后的命令
  - 危险命令清单用户可编辑（V2 企业版由公司统一下发且不可关闭）
- **断线自动重连**，重连后回滚内容还在，顶部提示「已重连」
- **`Ctrl+P` 快速跳转**：输三个字母直达任意主机或库，不用点侧栏

**V1 不做**　串口连接、Telnet、RDP/VNC、堡垒机协议对接。

## 10. 文件管理

**是什么**　终端旁边的文件面板，不是独立的 FTP 客户端。

**用户看到什么**　双栏，左边本地右边远程，拖拽即传输，底部是传输队列
（进度 / 速度 / 剩余时间，支持暂停和断点续传）。

**关键交互**

- **不需要重新登录。** 点开文件面板直接用当前 SSH 连接，不再输一次密码。
- **和终端双向联动（最痛的点）**
  - 终端 `cd` 到某个目录 → 文件面板一键跟过去
  - 文件面板选中目录 → 一键让终端 `cd` 过去
- 小文件双击直接编辑并保存回远程（自动留备份），大文件提示用终端编辑
- 右键：改权限、改属主、压缩/解压、算 MD5、复制路径

**V1 不做**　目录 diff、定时同步、批量重命名。

---

## 11. 日志管理

**是什么**　结构化的 `tail -f`，不是日志分析平台。

**用户看到什么**　一个独立面板（不是终端 Tab），实时滚动，ERROR/WARN 自动着色，
顶部一个过滤输入框。

**关键交互**

- **实时过滤**：输关键字或正则，立刻过滤，且不中断跟随
- **暂停 / 继续**：暂停后可自由滚动和选择，继续时自动跳回底部
- **自定义高亮规则**：正则 + 颜色，可保存复用
- **多机合并视图**：同时订阅多台机器的同一个日志，按时间戳合并成一个视图 —— **运维刚需**
- 一键「把最近 200 行发给 AI 分析」

**为什么不直接在终端里跑 `tail -f`**
终端里的 tail 没法过滤（要重开）、没法暂停（会丢内容）、没法多机合并。
这是终端做不到而「一站式平台」能做到的事。

**V1 不做**　日志检索历史、告警规则、日志存档。

---

## 12. 历史

**是什么**　你干过的所有事都能找回来。分命令和 SQL 两种，不混在一起。

**用户看到什么**

命令历史（`Ctrl+Shift+R`）：

```
┌─────────────────────────────────────────────────────────┐
│ 🔍 docker                          [全部主机 ▾] [全部 ▾] │
├─────────────────────────────────────────────────────────┤
│ ✓ docker compose up -d        web-01  /srv/app   2小时前 │
│ ✗ docker ps -a | grep redis   web-02  ~          昨天    │
│ ✓ docker logs -f api --tail   本地    ~/proj     上周    │
└─────────────────────────────────────────────────────────┘
      ↑ 成功绿 / 失败红，一眼看出哪条能直接用
```

**关键交互**

- 记录：命令、时间、目录、主机、**退出码**、耗时
- **跨主机搜索**：在本地也能搜到「上周在 web-01 上敲的那条」
- 按主机 / 目录 / 成功失败筛选
- SQL 历史单独一份：SQL、连接、耗时、影响行数、是否报错，可收藏为「常用查询」
- **含密码或 token 的命令自动打码后再存**

**隐私承诺**　历史**只存本机，不上传**。企业版是否上报由公司策略决定，
且必须在界面上明确告知用户。

**V1 不做**　历史多端同步、团队共享命令库。

## 13. 数据库

**是什么**　够用的数据库工作台。**不跟 Navicat 比功能多，比上下文连通。**

### 竞品判断（决定我们做什么）

| 产品 | 强项 | 我们的对策 |
|---|---|---|
| Navicat | 国内最流行，图形化完整，即装即用 | 不比功能面 |
| DBeaver | 开源，支持 80+ 种数据库 | 不比广度 |
| DataGrip | 补全强，**已对非商业用途免费** | 最危险的对手 |
| Bytebase | SQL 审核 + 治理，**审批锁在企业版收费** | ✅ 验证了 V2 的付费点 |
| Archery / Yearning | 国内主流开源 SQL 审核，**均无商业版，企业只能自己二次开发** | ✅ 这是市场缺口 |

**结论**：V1 用「同一棵树、同一条隧道、同一份 AI 上下文」赢，不用功能数量赢。
V2 往「SQL 审核 + 审批 + 审计」打 —— 那里有人付钱且没有好产品。

### 用户看到什么

- 左侧 Schema 树：库 → 表 → 列 / 索引 / 视图
- 中间 SQL 编辑器：补全 + 高亮 + 一键格式化
- 下方结果网格：可直接改单元格、按类型给编辑器（日期给日历、枚举给下拉）
- 执行计划可视化

### 关键交互（三个必须做对的）

**① 自动复用 SSH 隧道**
数据库挂在哪台 SSH 主机下，就自动走那台机器的现有连接建隧道。
**用户不需要再填一遍跳板信息。** 这是「一站式」最能被直接感知的一处。

**② 大结果集不卡死**
默认分页拉取，滚到底再拉下一页。**绝不一次性把一百万行拉进来。**

**③ 写操作有安全网**
- 默认**手动提交**：UPDATE / DELETE 之后要显式点提交
- 执行不带 `WHERE` 的 UPDATE / DELETE → 强制二次确认，并显示预估影响行数
- **生产库默认只读**，要写必须显式切换（切换动作会被记录）

### 支持范围
V1：**MySQL + PostgreSQL**。导出 CSV / JSON / SQL / Excel。

**V1 不做**　ER 图、报表、数据同步、存储过程调试、备份还原、用户权限管理。

## 14. AI

**是什么**　不是聊天框，是一个能看见你所有面板的助手。

### 三个入口

| 入口 | 快捷键 | 干什么 |
|---|---|---|
| **行内补全** | 自动 | 见 §8 第 ③ 层 |
| **命令生成** | `Ctrl+K` | 说人话 → 出命令，回车前可改，**永不自动执行** |
| **侧边对话** | `Ctrl+L` | 多轮，能调工具 |

### AI 能看见什么

终端最近 N 行 · 当前目录 · 上条命令和它的退出码 · Git 分支和状态 ·
当前数据库表结构 · 当前 SQL · 操作系统信息

**必须有一个可展开的「AI 将看到这些」面板。**
企业客户问的第一个问题一定是「你把我什么数据传出去了」，这个面板就是答案。
每一项都可以单独关掉。

### 安全承诺

> **AI 永远不会自己敲回车。**

AI 只能提出建议 → 用户看到完整命令 → 确认 → 才执行 → 全程留记录。
危险命令（§9 那份清单）额外再确认一次。V2 企业版可配置为需要主管审批。

### 模型
支持 Claude / OpenAI / DeepSeek / 通义 / 本地模型。
**企业版必须能指向公司内网自建的模型服务** —— 这是私有化的前提。

**V1 不做**　AI 自主多步执行（Agent 模式）、AI 编辑代码文件。

---

## 15. 主题 / 皮肤

**是什么**　整个应用换肤，不只是终端配色。

**用户看到什么**
一个主题包同时定义：终端配色、侧栏、Tab 栏、各面板、数据库结果网格、代码高亮。
**改配置立刻生效，不用重启。**

**关键交互**

- 内置：Catppuccin（4 变体）、Tokyo Night、Dracula、Nord、Solarized、One Dark、GitHub Light
- **可导入 iTerm2 和 Windows Terminal 的配色文件** —— 又是迁移成本
- 主题是单个文件，可分享、可导入导出
- 跟随系统深浅色自动切换（深色浅色各指定一个）
- **每个连接可以覆盖主题** —— 生产环境标红（见 §9）

**外观细项**（这些才是"好看"的真正来源）

- 字体：字族、字号、行高、字间距、连字开关、**中文单独设置字体**（中文用户刚需）
- 背景：不透明度、毛玻璃、背景图
- 光标：形状、是否闪烁、**移动时的平滑动画**
- 内边距、Tab 栏放上面还是下面、圆角

**V1 不做**　主题在线市场、可视化主题编辑器（先手改文件 + 实时预览）。

## 16. 快捷键

**四条原则**

1. **全部可重绑**，没有写死的键
2. **提供预设方案**：默认 / iTerm2 / Windows Terminal / Xshell / VS Code，一键切换
3. **冲突时明确提示**
4. **和 shell 冲突的键一律让给 shell**

第 4 条最容易做错。`Ctrl+C/D/Z/L/R/W/U/A/E` 全部传给终端，
我们自己的功能改用 `Ctrl+Shift+*`（macOS 用 `Cmd+*`）。

> **`Ctrl+R` 让给 shell，我们的历史搜索用 `Ctrl+Shift+R`。**
> 可以在设置里一键改成由我们接管 —— 这条请你确认，因为历史搜索是我们的卖点。

### 默认键位

| 功能 | macOS | Windows / Linux |
|---|---|---|
| 新建 / 关闭 Tab | `Cmd+T` / `Cmd+W` | `Ctrl+Shift+T` / `Ctrl+Shift+W` |
| 切 Tab | `Cmd+1..9` `Cmd+[ ]` | `Ctrl+1..9` `Ctrl+Tab` |

## 17. 稳定性（产品承诺）

用户能感知到的稳定性，就是下面这五条承诺：

> **① 界面崩了，你的 SSH 会话不断。**
> 应用崩溃、显卡驱动出问题、甚至你主动重启应用去装更新 ——
> 重新打开后，所有连接还在，正在跑的命令还在跑，正在传的文件还在传。

> **② 一个面板出问题，不影响其它面板。**
> 出问题的那个面板显示「已崩溃，点击重载」，其它 Tab 照常工作。

> **③ 画面出问题也不会白屏。**
> 自动切到兼容模式并提示你，绝不直接退出。

> **④ 关多久都不丢现场。**
> 窗口布局、打开的 Tab、每个 Tab 的目录，异常退出后下次启动问你要不要恢复。

> **⑤ 崩溃报告不会偷偷上传。**
> 本地生成，你看过、点了同意才发。企业版由公司策略决定，且必须脱敏。

另外两条硬性约束（不做就一定会把内存撑爆）：
**回滚内容再多也不吃内存**；**数据库查出来的行再多也不吃内存**。

## 18. 插件

**是什么**　V1 只定接口，**不做市场**。

**产品层面的唯一承诺**

> **插件崩了、卡死了，绝不影响主程序。**

**V1 定义的能力（不全部实现）**
注册面板 · 注册命令（自动出现在命令面板）· 注册补全来源 ·
注册主题 · 注册数据库驱动 · 订阅终端事件

**做法**　V1 自己先用这套接口做 1-2 个官方插件（比如一个主题包、一个数据库驱动），
吃自己的狗粮验证接口设计。

**V2 企业版**　允许加载哪些插件由公司下发白名单。

**V1 不做**　市场、评分、自动更新、权限沙箱。

## 19. 配置

### V1（个人版）

全部是本地文件，用户可以自己丢进 Git 管理。**不做云同步。**

### V2（企业版）—— 但 V1 必须先把产品形态定死

配置有三层，上面覆盖下面：

```
   公司下发的策略      ← V2 新增，最高优先级，可标记为「锁定」
        ↓
   你自己的设置        ← V1 就有
        ↓
   默认值
```

**V1 必须先做出来的产品行为**（现在做几乎不花时间，以后补要改遍每一个设置项）：

> 每个设置项都要能显示成「已被公司锁定」的状态 —— 灰色 + 🔒 图标 + 鼠标悬停
> 提示「此项由 IT 部门统一管理」。V1 这个状态永远不出现，但界面上要预留。

### V2 公司能下发什么（先定清单）

AI 模型地址和密钥 · SSH 主机和分组 · 数据库连接 · 主题和品牌 ·
快捷键方案 · 危险命令黑名单 · 插件白名单 · 审计上报地址 · 更新策略

**一条现在就要遵守的规则**：
**连接信息和密码分开存。**
V1 密码存系统钥匙串。V2 企业版要做到密码根本不落到员工电脑上 ——
如果 V1 把密码和连接配置混在一个文件里，V2 就得重做。

# 第四部分 · 范围与节奏

## 20. 里程碑

| 时间 | 交付 | 验收标准 |
|---|---|---|
| **第 4 周 · Beta** | 主界面 + 终端 + SSH 连接管理 + 主题 + 快捷键 + 补全①② + AI 三入口 + 稳定性承诺①②③ | **自己能全天当主力终端用** |
| **第 8 周 · 1.0** | ＋数据库 + 文件面板 + 日志面板 + 历史 + 补全③ + 插件接口 + 稳定性全部五条 | **能替代 Xshell + Navicat 的日常 80% 场景** |

## 21. 排期紧张时的砍单顺序

**先砍**：文件面板 → 日志面板 → 插件接口
**绝不砍**：自动补全、稳定性承诺、SSH 会话导入

理由：补全是唯一让 toC 用户留下的功能；稳定性是唯一让 toB 用户敢用的前提；
会话导入是用户愿意换过来的前提。这三条掉了，产品就没有存在理由。

## 22. 需要你尽快拍板的事

1. **`Ctrl+R` 到底让不让给 shell**（§16）—— 影响补全和历史两个模块的交互设计
2. **V1 数据库只做 MySQL + PostgreSQL 是否接受**（§13）
3. **V1 不做云同步是否接受**（§19）
4. **第 4 周 Beta 的验收标准「自己能全天当主力终端用」是否认可** —— 这决定了砍东西的底线
