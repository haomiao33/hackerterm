# HackerTerm V1 产品设计

> 状态：**草案，待评审**
> 日期：2026-08-07
> 定位：开发者一站式平台 —— 终端 · SSH · 数据库 · AI 四合一
> 本文只谈产品。技术栈结论见文末附录，V1 期间不再变更。

---

## 0. 一句话定位

> **把「连上去」「看明白」「改下去」这三件事收在一个窗口里，并且让 AI 同时看得见这三件事。**

不是更快的终端（Ghostty 已经够快），不是更好的 Navicat（比不过），
而是**唯一一个终端和数据库共享连接、共享隧道、共享 AI 上下文的工具**。

### 我们明确不做的（V1）

| 不做 | 理由 |
|---|---|
| 超过 2 种数据库驱动 | DBeaver 支持 80+ 种，广度赛道已死 |
| ER 图 / 报表 / 数据同步 | Navicat 的地盘，且与"一站式"叙事无关 |
| 自研 GPU 渲染器 | glyphon 已有，省 3-6 人月 |
| 插件市场 | V1 只留接口，不做生态 |
| 移动端 / Web 端 | 分散精力 |
| 会话录制回放 / 四眼审批 | V2 企业版，属 PAM 级 |

## 1. 主界面形态

### 决策：可折叠侧栏（默认展开），`Ctrl/Cmd+B` 收起

```
┌──────────────────┬──────────────────────────────────────────────┐
│ 🔍 搜索连接       │  ~/proj ×  │  web-01 ×  │ orders_db × │ + │🤖│
│                  ├──────────────────────────────────────────────┤
│ ▼ 最近            │ ~/proj $ cargo build                         │
│   ● web-01   2m  │    Compiling hackerterm v0.1.0               │
│   ○ orders_db    │ error[E0308]: mismatched types               │
│                  │   --> src/main.rs:42:9                       │
│ ▼ 生产环境 🔒     │                                              │
│   ● web-01       │ ~/proj $ █                                   │
│   ○ web-02       │                                              │
│   🗄 orders_db    │                                              │
│                  │                                              │
│ ▼ 本地            │                                              │
│   🖥 zsh          │                                              │
│   🗄 dev_mysql    │                                              │
│                  ├──────────────────────────────────────────────┤
│ ＋ 新建连接       │ 🤖 构建失败 · Ctrl+K 分析 · Ctrl+L 打开 AI    │
└──────────────────┴──────────────────────────────────────────────┘
```

**为什么是这个形态**：toC 开发者按 `Ctrl+B` 收起就是纯终端（Ghostty 体验）；
toB 运维展开就是 Xshell/FinalShell 体验。**更重要的是：V2 企业下发的连接必须有落点**——
带 🔒 的分组就是企业策略下发的，用户不可删改。
如果 V1 做成纯终端形态，V2 要凭空长出一棵树，那不是 UI 改动，是信息架构重做。

### 侧栏节点类型

| 图标 | 类型 | 双击行为 |
|---|---|---|
| 🖥 | 本地 Shell | 新建终端 Tab |
| ● / ○ | SSH 主机（● 已连接 / ○ 未连接） | 新建终端 Tab 并连接 |
| 🗄 | 数据库 | 新建 DB Tab |
| 📁 | 文件浏览（挂在 SSH 主机下） | 打开文件面板 |
| 📄 | 日志订阅（挂在 SSH 主机下） | 打开日志面板 |
| 🔒 | 企业策略分组（V2） | 只读，不可删改 |

**关键设计**：文件、日志不是独立的顶层功能，它们是**挂在连接下面的子能力**。
这保证了"一个连接 = 一条通道 = 终端/文件/日志/DB 全部复用"。

## 2. 终端

### 2.1 基础能力（对齐 Ghostty，不做减法）

- Tab + 任意方向 Split（水平/垂直，可嵌套）
- 24 位真彩色、粗体/斜体/下划线/删除线
- 连字（Fira Code / JetBrains Mono）、Emoji、CJK 宽字符正确对齐
- OSC 8 超链接（可 Ctrl+点击）、OSC 7 报告 cwd（新开 Tab 继承目录）
- 鼠标上报、Bracketed Paste（防止粘贴多行被直接执行）
- 无限 scrollback（分页 + 磁盘换出，见 §2.3）
- 搜索（正则、大小写、全 scrollback）

### 2.2 "丝滑"的具体定义（可验收，不是形容词）

| 指标 | 目标 | 怎么测 |
|---|---|---|
| 冷启动到可输入 | **< 300ms** | 打点计时 |
| 按键到屏幕显示 | **< 16ms**（1 帧） | typometer 类工具 |
| 大量输出吞吐 | `yes` / `cat 大日志` 不掉帧、不卡 UI | 眼测 + 帧率计数 |
| 高刷屏 | 跟随显示器刷新率（120Hz 就跑 120Hz） | — |
| 窗口 resize | 拖动过程中终端内容实时重排，无白屏 | 眼测 |
| 空闲 CPU | **0%**（无输出时不重绘） | 活动监视器 |

最后一条是很多 GPU 终端做砸的地方：无脑每帧重绘会让笔记本风扇狂转。
**必须做 damage-driven 重绘 —— 只有内容变化才触发一帧。**

### 2.3 Scrollback 存储

不用 `Vec<String>`。分页 + 冷热分离：

```
最近 10,000 行   →  内存（完整 Cell 属性：颜色/样式/宽度）
更早的           →  每 4096 行一页，压缩后写入磁盘缓存
搜索             →  先搜内存，再流式扫磁盘页
```

无限回滚不吃内存。磁盘缓存随会话关闭清理（企业版可配置为**禁止落盘**）。

## 3. 自动补全（**V1 最核心的差异化**）

这是你点名"比较核心"的一项，我认为它是 V1 唯一一个能让 toC 用户
"用了就回不去"的功能。设计成**三层融合**：

```
你输入： git ch|
         ↓
   ┌─────────────────────────────────────────────┐
   │ ▸ git checkout            切换分支          │ ← ② 历史 (你上周用过 40 次)
   │   git cherry-pick         拣选提交          │ ← ① 静态 spec
   │   git check-ignore        调试 gitignore    │ ← ① 静态 spec
   │ ─────────────────────────────────────────── │
   │ ▸ git checkout feature/auth-fix             │ ← ② 历史 + 当前仓库实际分支
   │ ▸ git checkout -b fix/E0308-mismatched      │ ← ③ AI（读到了刚才的报错）
   └─────────────────────────────────────────────┘
```

### 三层来源

| 层 | 来源 | 覆盖 | 延迟要求 |
|---|---|---|---|
| **① 静态 spec** | Fig 的 completion spec 生态（声明式 schema，开源，被 Amazon Q 继承；inshellisense 覆盖 600+ 命令） | 命令、子命令、flag、参数类型 | < 5ms |
| **② 历史 frecency** | 本机命令历史，按「频率 × 新近度 × 当前目录 × 当前主机」排序 | 你的真实习惯 | < 5ms |
| **③ AI 补全** | 当前 buffer + cwd + git 状态 + 上条命令退出码 | 「我想干什么」 | 异步，不阻塞 |

**必须遵守的交互规则**（这决定它是"神器"还是"烦人"）：

1. **① 和 ② 是同步的，永不卡住输入**。第 ③ 层异步到达后追加到列表底部，**绝不重排已显示的项**（重排会导致误选，是 Fig 早期最大的抱怨）。
2. **默认不弹窗**。只在行内显示一条最优建议的灰色 ghost text，`→` 接受。按 `Tab` 才展开完整列表。
3. **远程会话同样生效**。SSH 到服务器上，`systemctl re|` 依然补全 —— 靠本地 spec + 远程环境探测（首次连接时后台跑一次 `compgen`/`ls /usr/bin` 缓存），**不需要在服务器上装任何东西**。这是 Warp 和 Fig 都做得不好的地方，是你的机会。
4. **数据库 Tab 里补全的是 SQL**：表名、列名、JOIN 条件来自已加载的 schema。同一套 UI，不同的 provider。

### 待确认
- Fig completion spec 仓库的许可证需在集成前由法务确认可商用。若不可用，退路是自建 spec（覆盖 top 50 命令约 2 周）+ 运行时 `--help` 解析。

## 4. SSH 与连接管理

### 4.1 连接配置项（新建连接表单）

| 分组 | 字段 |
|---|---|
| 基础 | 名称、分组、Host、Port、User、备注、标签色 |
| 认证 | 密码 / 私钥（含 passphrase）/ ssh-agent / 键盘交互 |
| 跳板 | 多级 Jump Host（选择已有连接作为跳板，可链式） |
| 隧道 | 本地转发 / 远程转发 / 动态(SOCKS)，可多条 |
| 会话 | 启动命令、编码、终端类型(TERM)、保活间隔、自动重连 |
| 外观 | 该连接专属主题（**生产环境标红**，防误操作） |
| 高级 | 环境变量、X11 转发、压缩 |

**必须支持导入**：`~/.ssh/config`、Xshell 会话、FinalShell 会话、PuTTY。
**迁移成本是国内用户换工具的第一障碍**，这一项的优先级高于很多"新功能"。

### 4.2 生产环境防误操作（差异化细节）

- 连接可标记为「生产」→ 该 Tab 整体色调变红，Tab 标题带 ⚠
- 在生产 Tab 里输入危险命令（`rm -rf`、`DROP`、`TRUNCATE`、`shutdown`、`kill -9`）时，
  回车前弹出确认，显示**完整解析后的命令**
- 危险命令列表可配置；**V2 企业版由策略强制下发且用户不可关闭**

### 4.3 连接健康

- 断线自动重连（指数退避），重连后恢复 scrollback，顶部显示「已重连」条
- 侧栏节点实时显示连接状态（●已连 / ◐连接中 / ○断开 / ⊗失败）

## 5. 文件管理

### 决策：不做独立的 FTP 客户端，做「终端旁边的文件面板」

- 挂在 SSH 连接下，走**同一条已建立的 SSH 连接**（SFTP subsystem），不重新认证
- 双栏（本地 ↔ 远程）拖拽传输，队列显示进度/速度/剩余时间，支持断点续传
- **与终端联动（关键）**：
  - 终端 `cd` 到某目录 → 文件面板可一键跟随（OSC 7 已经告诉我们 cwd 了）
  - 文件面板选中目录 → 一键在终端 `cd` 过去
  - 这个双向联动是 WinSCP/FinalShell 用户最痛的点
- 内置编辑器：小文件直接编辑保存回远程（带备份），大文件提示用终端 vim
- 右键：权限修改(chmod)、属主(chown)、压缩/解压、计算 md5

### V1 不做
批量同步、目录 diff、定时任务。

## 6. 日志管理

### 决策：不做日志分析平台，做「结构化的 tail -f」

挂在 SSH 连接下，选择文件路径后开一个**日志面板**（不是终端 Tab）：

- 实时跟随（底层就是 `tail -f`，但输出进的是结构化视图而不是终端 buffer）
- **高亮规则**：ERROR/WARN/INFO 自动着色；自定义正则高亮规则可保存
- **实时过滤**：输入关键字/正则即时过滤，不中断跟随
- **暂停/继续**，暂停时可自由滚动和选择，继续时跳回底部
- **多文件合并视图**：同时订阅多台机器的同一个日志，按时间戳合并（运维刚需）
- 一键「把最近 200 行发给 AI 分析」

### 为什么单独做面板而不是终端里跑 tail
终端里跑 `tail -f` 无法过滤（要重开）、无法暂停（会丢）、无法多机合并。
这是一个终端做不到但"一站式平台"能做到的事，成本不高（约 1 周），
**是很好的 demo 素材**。

## 7. 历史

分两种，不要混：

### 7.1 命令历史
- 全局记录：命令、时间、cwd、主机、退出码、耗时
- `Ctrl+R` 打开搜索面板：模糊搜索 + 按主机/目录/成功失败筛选
- **跨主机**：在本地也能搜到"我上周在 web-01 上敲的那条命令"
- 失败的命令标红，成功的标绿 —— 一眼看出哪条能用
- 敏感命令（含密码/token 的）自动脱敏后再存

### 7.2 SQL 历史
- 记录：SQL、连接、耗时、影响行数、是否报错
- 可收藏为「常用查询」，支持命名和参数占位
- V2 企业版：SQL 历史上报控制面用于审计

### 隐私
本地历史默认**只存本机**，不上云。企业版由策略决定是否上报（且必须在 UI 明示）。

## 8. 数据库工作台

### 8.1 V1 范围

**只做 MySQL + PostgreSQL。** 理由见开头调研结论。

| 做 | 不做（V1） |
|---|---|
| 连接（含走 SSH 隧道） | ER 图 |
| Schema 树（库/表/列/索引/视图） | 报表 |
| SQL 编辑器（补全 + 高亮 + 格式化） | 数据同步/传输 |
| 结果网格（虚拟滚动、可编辑、类型化编辑器） | 存储过程调试 |
| 执行计划（EXPLAIN 可视化） | 备份还原 |
| 导出 CSV/JSON/SQL/Excel | 模型设计 |
| 事务控制（手动提交模式） | 用户权限管理 |

### 8.2 三个必须做对的细节

**① SSH 隧道复用**
选择数据库时，如果它挂在某个 SSH 主机下，**自动复用已建立的 SSH 连接建隧道**，
不要求用户再填一遍跳板信息。这是"一站式"最能被感知的一处。

**② 大结果集不能卡死**
默认 `LIMIT 500` 分页流式拉取，滚到底再拉下一页。
**绝不一次性把 100 万行拉进内存** —— 这是 Navicat 常被吐槽的地方。

**③ 写操作的安全网**
- 默认**手动提交模式**（autocommit off），UPDATE/DELETE 后要显式提交
- 执行不带 `WHERE` 的 UPDATE/DELETE 时强制二次确认并显示预估影响行数
- 生产库连接默认**只读模式**，要写必须显式切换（切换动作进审计）

### 8.3 AI 在 DB 里做什么
- 自然语言 → SQL（带 schema 上下文）
- 解释一段陌生 SQL 在干什么
- 慢查询分析：读 EXPLAIN 结果给优化建议
- **跨面板**：终端里报错 `Duplicate entry for key 'uk_order_no'` → AI 能直接定位到 `orders` 表的哪个唯一索引

## 9. AI

### 交互形态：三个入口，不是一个聊天框

| 入口 | 快捷键 | 场景 |
|---|---|---|
| **行内补全** | 自动 | §3 第 ③ 层 |
| **命令生成** | `Ctrl+K` | 自然语言 → 命令，回车前可编辑，**永不自动执行** |
| **侧边对话** | `Ctrl+L` | 带上下文的多轮，可执行工具调用 |

### 上下文（自动采集，用户可见可关）

终端 buffer 最近 N 行 · cwd · 上条命令与退出码 · git 分支与状态 ·
当前 DB schema · 当前 SQL · 系统信息(OS/shell)

**必须在 UI 上有一个可展开的「AI 将看到这些」面板**。
企业客户第一个问题一定是"你把我什么数据传出去了"，这个面板就是答案。

### 执行安全
AI 永远不直接写 PTY。它产出 `ToolCall` → 用户看到完整命令 → 确认 → 执行 → 记审计。
高危命令（§4.2 列表）额外二次确认。**V2 企业版可配置为需审批。**

### 模型
V1 支持：Claude / OpenAI / DeepSeek / 通义 / 本地 Ollama。
**企业版必须支持指向内网自建模型端点**（这是私有化的硬性前提）。

## 10. 皮肤 / 主题

### 10.1 覆盖范围
主题不只是终端配色，是**整个应用**：终端 16 色 + 前景背景光标选中、
侧栏、Tab 栏、面板、DB 结果网格、代码高亮，全部由一个主题文件定义。

### 10.2 主题文件
- 单文件（TOML），可分享、可导入导出
- 内置：Catppuccin (4 变体)、Tokyo Night、Dracula、Nord、Solarized、One Dark、GitHub Light
- **兼容导入 iTerm2 `.itermcolors` 和 Windows Terminal 配色** —— 迁移成本
- 跟随系统深浅色自动切换（可指定深色主题和浅色主题各一个）

### 10.3 外观细项（这些才是"丝滑"的观感来源）
- 字体：字族、字号、行高、字间距、连字开关、**CJK 独立字体设置**（中文用户刚需，很多终端做不好）
- 背景：不透明度、毛玻璃模糊、背景图片
- 光标：形状(块/竖线/下划线)、闪烁、**平滑移动动画**
- 内边距、Tab 栏位置(上/下)、圆角
- **每个连接可覆盖主题**（生产环境标红，见 §4.2）
- **实时预览 + 热加载**：改配置文件即时生效，不重启

## 11. 快捷键

### 11.1 原则
1. **全部可重绑**，无硬编码
2. **提供预设方案**：默认 / iTerm2 / Windows Terminal / Xshell / VS Code —— 一键切换，降低迁移成本
3. **冲突检测**：绑定冲突时 UI 明确提示
4. **终端优先**：默认情况下，与 shell 冲突的键（`Ctrl+C/D/Z/L/R/W/U/A/E`）**一律传给终端**，应用自身功能改用 `Ctrl+Shift+*` 或 `Cmd+*`

第 4 条是很多终端做错的地方。`Ctrl+R` 尤其危险 —— 我们要用它做历史搜索，
但 shell 自己也有 `Ctrl+R`。**决策：`Ctrl+R` 传给 shell，我们的历史搜索用 `Ctrl+Shift+R`。**
可在设置里一键改成接管。

### 11.2 默认键位（macOS 用 Cmd，Win/Linux 用 Ctrl+Shift）

| 功能 | 键 |
|---|---|
| 新建 Tab / 关闭 Tab | `Cmd+T` / `Cmd+W` |
| 切换 Tab | `Cmd+1..9` / `Cmd+[` `]` |
| 垂直/水平 Split | `Cmd+D` / `Cmd+Shift+D` |
| 焦点在 Split 间移动 | `Cmd+Alt+方向键` |
| 折叠侧栏 | `Cmd+B` |
| **命令面板**（万能入口） | `Cmd+Shift+P` |
| **连接快速跳转** | `Cmd+P` |
| AI 命令生成 / AI 对话 | `Cmd+K` / `Cmd+L` |
| 终端内搜索 | `Cmd+F` |
| 命令历史搜索 | `Cmd+Shift+R` |
| 设置 | `Cmd+,` |
| 清屏 | `Cmd+K` 冲突 → 用 `Cmd+Shift+K` |

`Cmd+P` 连接快速跳转是高频操作：输三个字母直达任意主机或库，不用点侧栏。

## 12. 防崩溃与稳定性

你点名了这一项，我认为它需要一个**架构级**的决定，而不是"多写点 try-catch"。

### 12.1 核心决策：会话与 UI 进程分离（tmux 模型）

```
┌─────────────────┐        ┌──────────────────────────┐
│  ht-ui (GUI)    │ ◄────► │  ht-sessiond (后台进程)   │
│  渲染/交互/AI    │  IPC   │  PTY · SSH · DB 连接      │
│  崩了 → 重启     │        │  scrollback · 传输队列     │
└─────────────────┘        └──────────────────────────┘
        UI 崩溃 / 更新重启 → 会话全部存活，重连后原样恢复
```

**为什么 V1 就要做**：这个拆分事后补极其困难（要把所有会话状态从 UI 里剥离）。
现在做的增量成本约 1-2 周，收益是：

- GUI 崩溃、GPU 驱动崩溃、应用更新重启 → **SSH 会话和正在跑的命令不中断**
- 大文件传输不会因为你关了窗口而中断
- 未来做"接管远程会话"（像 tmux attach）几乎免费

### 12.2 其它硬性要求

| 措施 | 说明 |
|---|---|
| Panic 边界 | 每个 Tab/面板独立 `catch_unwind`，**单个面板崩溃只影响该面板**，其它 Tab 继续工作，崩溃面板显示"已崩溃，点击重载" |
| 禁用 unwrap | 项目内 lint 禁止 `unwrap()`/`expect()` 出现在非测试代码 |
| GPU 降级 | wgpu 初始化失败或驱动异常 → 自动回退软件渲染并提示，**绝不白屏或直接退出** |
| 状态快照 | 布局/Tab/cwd 每 30s 快照，异常退出后下次启动询问是否恢复 |
| 崩溃上报 | 本地生成崩溃报告，**默认不自动上传**，用户确认后才发送（企业版由策略决定，且必须脱敏） |
| 内存上限 | scrollback 磁盘换出（§2.3）；DB 结果集分页（§8.2）；两个最容易 OOM 的地方都封死 |
| 更新 | 增量更新 + 失败自动回滚；**企业版可完全禁用自动更新**（内网离线） |

## 13. 插件

### 决策：V1 只留接口，不做市场

- **进程外**：插件是独立进程，通过 JSON-RPC over stdio 通信。
  **插件崩溃/卡死绝不影响主程序**（这是 V1 唯一必须保证的插件属性）
- V1 内部先用这套机制实现 1-2 个官方"插件"（比如一个主题包、一个 DB 驱动），
  **自己吃自己的狗粮，验证接口设计**
- 能力面（V1 定义，不全部实现）：
  注册面板 · 注册命令(进命令面板) · 注册补全 provider ·
  注册主题 · 注册 DB 驱动 · 订阅终端事件
- **不做**：市场、评分、自动更新、沙箱权限系统 —— 全是 V2+ 的事
- 企业版：**插件白名单由控制面下发**，非白名单插件不允许加载

## 14. 配置同步

### 14.1 V1（toC）
- 配置全部是本地文件（TOML），可手动放进 Git 自己管
- **不做云同步**。做云同步意味着要有账号体系、服务端、加密方案，
  是一个独立子项目，会吃掉 V1 一半时间

### 14.2 V2（企业）—— 但 V1 必须留好口子
配置读取全部走一个抽象层，V1 只有本地实现，V2 加远程策略层：

```
  企业控制面下发的策略  ← V2 新增，优先级最高，可标记为「锁定」
          ↓  覆盖
  用户本地配置          ← V1 就有
          ↓  覆盖
  默认值
```

**V1 必须做的三件小事**（现在几乎零成本，以后补要改遍全部设置项）：
1. 每个配置项支持「锁定」标记，锁定时 UI 显示为灰色 + 🔒 且不可编辑
2. 所有配置读取走统一入口，不允许任何模块直接读文件
3. 配置变更走统一的订阅通知（本地热加载和远程推送用同一条路）

### 14.3 V2 企业能下发什么（先定清单，V1 据此设计数据结构）
AI 模型端点与密钥 · SSH 主机与分组 · 数据库连接 · 主题与品牌 ·
快捷键方案 · 危险命令黑名单 · 插件白名单 · 审计上报地址 · 更新策略

**凭据下发的原则（V1 就要遵守）**：连接信息和凭据分离存储。
V1 凭据存 OS keychain；V2 企业版凭据可以完全不落地（内存态，控制面按需下发）。
如果 V1 把密码和连接配置混在一个 TOML 里，V2 就要重做。

## 15. V1 里程碑

| 时间 | 交付 | 验收 |
|---|---|---|
| **第 4 周 · Beta** | 主界面框架 + 本地终端 + SSH 连接管理 + 主题 + 快捷键 + 补全①② + AI 三入口 + 会话进程分离 | 自己能全天当主力终端用 |
| **第 8 周 · 1.0** | + MySQL/PostgreSQL 工作台 + 文件面板 + 日志面板 + 历史 + 补全③ + 插件接口 + 崩溃防护全套 | 能替代 Xshell + Navicat 的日常 80% 场景 |

### 风险与已知取舍
- **第 4 周 Beta 是紧的**。若延期，第一个砍的是「文件面板」和「日志面板」（推到 1.0 之后），**不砍补全和防崩溃**。
- Fig completion spec 许可证若不可商用，补全①层需自建，Beta 顺延约 2 周。
- Windows 上的 IME（输入法候选框定位）和 ConPTY 兼容性是最大的未知数，需要在第 1 周就做技术验证，不能拖到最后。

## 附录：技术栈（已冻结）

| 层 | 选型 | 说明 |
|---|---|---|
| 语言 | Rust | — |
| 终端内核 | `alacritty_terminal` + `vte` | Apache-2.0，Zed 在用，省 6+ 人月 |
| 文字渲染 | `glyphon`（= cosmic-text + etagere + wgpu） | 现成的 GPU glyph atlas，Emoji/连字/CJK/fallback 全包 |
| UI | `egui` + `egui_extras::TableBuilder` | Table 自带虚拟滚动，直接用作 DB 结果网格 |
| GPU | `wgpu` → Metal / Vulkan / DX12 | 三平台一套代码 |
| 窗口 | `winit` | — |
| 配置 | TOML | 热加载 |
| 插件 | 进程外 JSON-RPC over stdio | 隔离优先 |

**已排除**：`gpui`（pre-1.0，API 不稳定，官方仅支持 macOS/Linux，Windows 移植困难 ——
而国内企业内网以 Windows 为主）；Electron（体积和内存在本品类会被目标用户直接否定）。
