> 状态：草案，持续更新 · 日期：2026-08-07

---

## 1. 一句话

> **终端、数据库、文件管理，都在一个软件里管。每个功能开在自己的 Tab 里。**

用户今天要装三个软件：终端（Xshell / iTerm2）、数据库（Navicat）、
文件传输（WinSCP / FinalShell）。三套连接配置，三个图标。

**不是说不用切换** —— 切 Tab 是正常的，本来就该切。
区别是：切的是同一个软件里的 Tab，不是三个软件的窗口。

---

## 2. 四条核心

**排期紧张时优先保这四条，其它都可以砍。**

### ① 都在同一个软件里管
终端、数据库、文件管理在一个软件里，一棵连接树管所有连接。

### ② SSH 要丝滑 —— 数据量大不能卡

| 场景 | 要求 |
|---|---|
| `cat` 一个几十 MB 的二进制文件 | 不卡死、不假死，能 `Ctrl+C` 立刻中断 |
| `tail -f` 高速刷屏的日志 | 持续跟得上，不掉帧，界面还能操作 |
| 同时开 10+ 个会话，多个在刷屏 | 每个都流畅，互不影响 |
| 大文件传输的同时敲命令 | 敲命令不卡顿 |
| 敲键盘 | 按下到显示 < 一帧（16ms） |
| 屏幕上没有输出时 | CPU 占用 0%，风扇不转 |

**必须做并发压力测试，不能只测单会话。**

### ③ 数据库不能卡 —— 尤其是结构解析和自动提示

DataGrip 的问题：自动提示做得好，但刷新数据库结构能卡死人。

| 场景 | 要求 |
|---|---|
| 连上一个有**几十个库、几百张表**的实例 | 树立刻能展开，**不等全部加载完**（用到哪个加载哪个） |
| 刷新数据库结构 | 后台加载，**界面不冻结**，可随时取消 |
| SQL 自动提示 | 表名列名秒出，**不能因为结构没加载完就没提示** |
| 查询返回几十万行 | 不卡死，滚到哪加载到哪 |
| 执行慢查询时 | 界面不冻结，能取消执行 |

**自动提示做到 DataGrip 的水平，结构加载要比 DataGrip 快。**

### ④ 不能崩溃 —— 一个 Tab 一个进程

> **这是硬条件：一个 Tab 崩了，绝不能影响其它 Tab。内存代价不用管。**

| 承诺 | 说明 |
|---|---|
| 一个 Tab 崩了，其它 Tab 照常工作 | 崩的那个显示「已崩溃，点击重开」 |
| 界面崩了，SSH 会话不断 | 重开后连接还在，正在跑的命令还在跑 |
| 画面出问题不白屏 | 自动切兼容模式并提示 |
| 异常退出后能恢复现场 | 窗口布局、打开的 Tab、每个 Tab 的目录 |

## 3. 连接树 + Tab

```
┌──────────────────┬────────────────────────────────┬──────────────┐
│ 🔍 搜索           │▐web-01 ×│▐orders_db ×│▐zsh ×│+ │ web-01    ⟩│
│                  │ ↑红·生产   ↑红·生产    ↑灰·本地│              │
│                  ├────────────────────────────────┤ CPU ▓▓▓░░ 62%│
│ ▐ 生产环境  ▼     │ [root@web-01 ~]# tail -f a.log │ 内存▓▓▓▓░ 78%│
│   ● web-01       │                                │     6.2/8 GB │
│   ○ web-02       │                                │              │
│   🗄 orders_db    │                                │ 磁盘          │
│ ▐ 测试环境  ▼     │                                │ /    ▓▓░░ 45%│
│   ○ test-01      │                                │ /data▓▓▓▓ 91%│← 红
│   🗄 test_mysql   │                                │              │
│ ▐ 本地      ▼     │                                │ ↑1.2M ↓340K  │
│   🖥 zsh          │                                │ 负载 0.8 1.2 │
│   🗄 dev_mysql    │                                │ 运行 42 天    │
│                  │                                │ Ubuntu 22.04 │
│                  │                                │  [展开详情]   │
└──────────────────┴────────────────────────────────┴──────────────┘
   ▲ 左边按分组着色      ▲ Tab 继承分组颜色        ▲ 右边服务器信息
                                                     ⟩ 可收起
```

树里放三种东西：**SSH 连接**、**数据库连接**、**分组**。
两种连接各自独立创建、独立配置，谁也不依赖谁。

### 每个功能开在自己的 Tab 里

| 打开的东西 | 开出来是什么 Tab |
|---|---|
| SSH 连接 | 终端 Tab |
| 数据库连接 | 查询 Tab |
| 管理文件 | 文件 Tab |

**Tab 可以分屏并排看，也可以拖出去成独立窗口。**

### 右键就是主要入口

| 右键位置 | 菜单 |
|---|---|
| **树的空白处 / 分组上** | 新建 SSH 连接 · 新建数据库连接 · 新建分组 · 设置分组颜色 |
| **一个 SSH 连接** | 打开终端 · **管理文件** · 编辑 · 复制 · 删除 |
| **一个数据库连接** | 打开查询 · 编辑 · 复制 · 删除 |
| **终端窗口里 / 终端 Tab 上** | **管理文件**（开当前这台服务器的文件 Tab，**进终端当前所在的目录**） |

## 4. 连接的组织方式

每个连接（SSH 和数据库都一样）可以设置：

| 属性 | 说明 |
|---|---|
| **标签** | 一个连接可打多个标签（如 `线上` `订单` `华东`），可按标签筛选 |
| **颜色** | 单独指定，覆盖所属分组的颜色 |
| **分组** | 可嵌套多级，拖拽移动 |
| **排序** | 手动拖拽排序，也可按名称 / 最近使用自动排 |

**颜色规则**：分组带颜色，Tab 继承分组颜色。
生产环境标红 → 侧栏该分组红色，从它开出来的**所有 Tab 都是红的**，
一眼看出当前 Tab 是不是生产环境。

## 5. SSH 连接配置

常规配置，对齐 Xshell / FinalShell 的水平即可。

### 常规
名称 · 分组 · 标签 · 颜色 · 主机 · 端口 · 用户名 · 备注

### 认证

| 方式 | V1 | 说明 |
|---|---|---|
| 密码 | ✅ | 存本机系统钥匙串 |
| 密钥文件 | ✅ | 支持带口令的密钥 |
| ssh-agent | ✅ | |
| 键盘交互 | ✅ | |
| **远程派发** | ❌ 留口子 | 企业管理端下发，V1 不做 |

> **V1 必须做**：每个连接标记来源是「本地」还是「远程下发」。
> V1 全是「本地」，但这个标记和对应界面状态（远程下发的不可编辑、带 🔒）现在就要有。

### 代理

**终端支持设置代理。**

| 选项 | 说明 |
|---|---|
| 不使用代理 | |
| **沿用系统代理** | 直接读系统的代理设置 |
| **自定义代理** | HTTP / SOCKS4 / SOCKS5，填地址、端口、用户名、密码 |

可以设一个全局默认代理，单个连接可以覆盖它。

### 跳板与隧道
多级跳板（可直接选已有连接当跳板）· 本地转发 / 远程转发 / 动态代理，可配多条

### 终端选项
编码（UTF-8 / GBK 等）· 终端类型 · 退格键行为 · 登录后自动执行的命令

### 高级
保活间隔 · 连接超时 · 断线自动重连 · 压缩 · X11 转发 · 环境变量

### 导入
支持从 **Xshell · FinalShell · PuTTY · `~/.ssh/config` · MobaXterm** 一键导入。

## 7. 终端

- 本地 Shell + SSH，多标签、任意方向分屏、可拖出独立窗口
- 真彩色、粗体/斜体/下划线、连字、Emoji、**中文等宽对齐正确**

- 链接可点击
- 新开 Tab 继承当前目录
- 粘贴多行时先确认，防止误粘贴直接执行
- 选中即复制（可关）、右键粘贴（可配）

## 8. 自动补全

**形态：像右键菜单一样弹出来，`Tab` 选择，和 DataGrip 差不多。**

### 铁律：绝对不能卡

> **可以没有补全，但绝对不能卡。**

- 补全**永远不阻塞输入**。查不到就不弹，用户该敲什么敲什么
- 这次没显示出来没关系，**后台慢慢刷新，下次就有了**
- 补全数据存在本地（本地库），**不是每次现查**
- 数据库结构没加载完时，用已经缓存的先顶上，加载完了自动更新

### 补什么

| Tab 类型 | 补什么 |
|---|---|
| 终端 | 命令、子命令、参数、路径；**SSH 到远程也要能补** |
| 数据库 | 库名、表名、列名、关键字、JOIN 条件 |

### 给 AI 留的口子
补全的候选来源要能挂第三方（后面接 AI 建议时直接插进去，不改现有逻辑）。
详见 §14。

## 9. 数据库功能

### 9.1 查询与结果

- 执行 SQL，**显示执行结果**（影响行数、耗时、报错信息）
- 结果网格：虚拟滚动，几十万行不卡
- 可直接改单元格
- 执行计划

### 9.2 复制与导出

**复制**（选中结果后）：

| 复制成 | 说明 |
|---|---|
| **INSERT 语句** | 直接拿去别的库执行 |
| **UPDATE 语句** | 按主键生成 |
| **CSV（逗号分隔）** | |
| 制表符分隔 | 粘进 Excel 用 |
| JSON | |

**导出**：同样支持上面这些格式，导成文件。

### 9.3 建库建表（DDL）

| 能力 | 说明 |
|---|---|
| 新建 / 修改 / 删除 **库** | 字符集、排序规则可选 |
| 新建 / 修改 / 删除 **表** | 可视化建表：列名、类型、长度、默认值、非空、注释 |
| 索引 | 普通 / 唯一 / 组合 |
| 外键 | 建、改、删 |
| 视图 | 至少能看 |
| **执行前先看 SQL** | 所有可视化操作，执行前都能看到实际要执行的 SQL，可复制走 |

最后一条很重要 —— 用户不信任"黑盒改我的表"，看到 SQL 才敢点确定。

### 9.4 危险操作必须提示

> **删除表、清空表、删除库、删除数据，全部要二次确认。**

确认框里要显示：要操作的对象名、**预估影响行数**、以及实际执行的 SQL。

### 9.5 导入导出（用数据库自带的工具）

> **直接调用系统自带的 `mysqldump` / `mysql` / `pg_dump` / `pg_restore`，不自己造。**
> 导出的文件和命令行导出完全一致，别人拿去用不会有兼容问题。

**导出**：整库 / 选中的表 → dump 原生格式（可选只结构 / 只数据 / 结构+数据）
**导入**：`.sql` 文件（含 dump 文件）流式执行，**几百 MB 也不能卡死**，显示进度、可取消

出错时要明确告诉用户**第几行出错、错在哪**，不能笼统报个失败。
本机没装 `mysqldump` / `pg_dump` 时，要给明确提示和解决办法。

### 9.6 数据库信息

版本 · 字符集 · 运行时长 · 当前连接数 / 最大连接数 ·
库大小 · 表数量 · 最大的几张表 · 当前正在执行的会话

### 9.7 支持范围
**V1 只做 MySQL 和 PostgreSQL。**

## 10. 文件管理

> **V1 保持简单：文件管理和终端没有联动关系。**
> 唯一的关联就是「从终端右键能打开它」，打开之后两边各走各的。

### 打开方式
- 右键 SSH 连接 → 管理文件（进 home 目录）
- **右键终端 → 管理文件（进终端当前所在的目录）**

> 拿不到终端当前目录时（比如刚连上还没 `cd`），退回 home 目录。

### 明确不做（V1）
- ❌ 终端 `cd` 之后文件面板自动跟随
- ❌ 文件面板切目录之后终端自动 `cd`
- ❌ 双栏（本地 ↔ 远程）对拷布局

**布局用单栏，只显示远程。** 本地文件通过拖拽进来、或点「上传」用系统文件框选。

### 必须有的

| 功能 | 说明 |
|---|---|
| **刷新按钮** | 手动刷新当前目录 |
| **上传 / 下载** | 拖拽 + 按钮两种方式，显示进度、速度、剩余时间 |
| **删除要提示** | 二次确认，显示要删的文件名和数量 |
| **覆盖要提示** | 同名文件时问：覆盖 / 跳过 / 保留两者，可「全部应用」 |
| **快速切换目录** | 顶部路径输入框，直接敲路径回车就跳 |
| **记住历史目录** | 路径框下拉出最近去过的目录 |

### 其它
- 新建文件夹、重命名、改权限、删除
- 小文件双击直接编辑并保存回远程
- 右键复制路径

## 11. 服务器信息（探测）

SSH 连上后自动探测并显示这台服务器的情况。

| 显示什么 | |
|---|---|
| CPU | 使用率、核数、型号、负载 |
| 内存 | 已用 / 总量、Swap |
| 磁盘 | 各挂载点已用 / 总量，**快满了标红** |
| 网络 | 实时上下行速率 |
| 系统 | 发行版、内核版本、开机时长 |
| 进程 | 占 CPU / 内存最高的几个 |

**要求**
- 后台探测，**不影响终端输入**
- 可以关掉（有些机器不希望被周期性执行命令）
- 频率可调
- 探测失败（权限不够、命令不存在）安静降级，不弹错误框骚扰用户

### 位置：终端 Tab 的右侧栏

**展开时**：右边一条窄栏，只显示关键几项（不做成大仪表盘）——
CPU / 内存 / 磁盘各挂载点 / 实时网速 / 负载 / 运行时长 / 系统版本。
底部一个「展开详情」，点了才看进程列表这些。

**收起时**：变成一个**便签**，贴在**右侧边缘上部**或**右上角**，点一下展开。

```
展开                              收起（贴右边缘上部）
┌────────────────┬──────────┐   ┌───────────────────────────┬─┐
│ 终端            │ web-01  ⟩│   │ 终端                      │服│
│                │CPU ▓▓▓ 62%│   │                          │务│
│                │内存▓▓▓▓78%│   │                          │器│
│                │磁盘 ▓▓  45%│   │                          │ ●│← 磁盘告警
│                │↑1.2M↓340K│   │                          │ ⟨│
└────────────────┴──────────┘   └───────────────────────────┴─┘

                                 收起（右上角浮标）
                                ┌──────────────────┬────────┐
                                │ 终端              │▣ 62% ●│← 悬停展开
                                │                  └────────┤
                                │                           │
                                └───────────────────────────┘
```

两种收起样式都可以，**默认用右上角浮标**（不占终端宽度，且视线自然落点）。
鼠标悬停时可以先浮出一个小卡片预览，点了才真正展开侧栏。

**收起状态下仍要能报警**：磁盘快满、CPU 长时间打满时，
便签上显示一个小红点，提醒用户展开看看。

展开/收起状态**按连接分别记住**（这台机器你习惯展开，那台习惯收起）。

## 12. 操作日志（地基）

> **所有操作都要留日志。V1 就做，存本地。**

这不是一个附属功能，是**三件事共同的地基**：

```
                    操作日志
                       │
        ┌──────────────┼──────────────┬──────────────┐
        ▼              ▼              ▼              ▼
    ① 历史查询      ② 自动补全      ③ 给 AI       ④ V2 企业审计
    用户翻自己      用得多用得近    上下文来源    上报管理端
    干过什么        的排前面                     谁干了什么
```

**所以它必须一次做对**：日志的字段设计要同时满足这四个用途，
不能先做个简陋的命令历史，以后再返工。

### 记什么

| 类型 | 记录内容 |
|---|---|
| **连接** | 连上 / 断开 / 连接失败 · 目标主机或库 · 时间 · 耗时 |
| **命令** | 命令 · 时间 · 目录 · 主机 · **退出码** · 耗时 |
| **SQL** | SQL · 连接 · 时间 · 耗时 · **影响行数** · 是否报错 |
| **DDL** | 建库 / 建表 / 改表 / 删表 / 清空 · 实际执行的 SQL |
| **文件** | 上传 / 下载 / 删除 / 重命名 / 改权限 · 路径 · 大小 |
| **导入导出** | dump 导入导出 · 库表范围 · 文件路径 · 结果 |

### 用户能看到什么

**命令历史**
- 跨主机搜索：在本地也能搜到「上周在 web-01 上敲的那条」
- 成功绿 / 失败红，一眼看出哪条能直接用
- 按主机 / 目录 / 成功失败筛选

**SQL 历史**
- 可收藏为常用查询

**操作记录**
- 一个总的时间线视图，能看到"我今天在这台机器上干了什么"

### 安全与隐私

| 要求 | 说明 |
|---|---|
| **自动脱敏** | 含密码、token、密钥的内容自动打码后再存 |
| **只存本机** | V1 绝不上传。企业版是否上报由公司策略决定，**且必须在界面上明确告知用户** |
| **可清除** | 用户可以清空全部或按时间范围清除 |
| **可关闭** | 用户可以关掉记录（关了之后补全和历史也就没了，要提示清楚） |

### 存储
本地库。**和补全共用同一套存储**，用得多、用得近的排前面。
要能扛住长期积累（几年、几十万条）而不变慢。

## 13. 皮肤

**一套皮肤同时管终端、数据库、文件管理和整个界面。**
换一次肤，全部一起变 —— 不是"终端有终端的配色，数据库有数据库的配色"。

**默认内置 2 套**（一深一浅），跟随系统深浅色自动切换。

可改：字体（**中文字体可单独设置**）· 字号 · 行高 ·
背景不透明度 · 光标形状 · 内边距

## 14. AI（V1 占位）

> **V1 先占位，只留口子，不做功能。先把基本盘做好。**

留口子的地方有两处，**现在必须设计好，否则以后要改逻辑**：

1. **补全的候选来源可以挂第三方** —— 以后接 AI 建议时直接插进候选列表
2. **上下文能被统一入口读取** —— 终端最近内容、当前目录、上条命令退出码、
   当前数据库结构、当前 SQL，加上 **§12 的操作日志**，要能被一个统一入口拿到

界面上先留入口位置（比如工具栏一个 🤖 图标），点了提示「即将推出」。

## 15. 快捷键

| 要求 | 说明 |
|---|---|
| **有一套默认键位** | 覆盖全部功能，开箱即用 |
| **跟随系统习惯** | macOS 用 `Cmd`，Windows / Linux 用 `Ctrl`，各平台一套 |
| **可迁移** | 预设方案一键切换：**DBeaver · DataGrip · Xshell · iTerm2 · Windows Terminal · VS Code** |
| **可修改** | 快捷键管理界面，任意重绑，冲突时明确提示，可重置 |

> 待定：和 shell 冲突的键（尤其 `Ctrl+R`）要不要抢过来。见 §18。

## 16. V1 范围

### 做

| 模块 | 做什么 |
|---|---|
| **终端** | 本地 Shell + SSH，多标签、分屏、拖出独立窗口、**代理** |
| **连接树** | 统一管 SSH 和数据库连接；标签、颜色、分组、排序、搜索、右键；支持导入 |
| **数据库** | 只做 MySQL / PG。查询、改数据、结构树、自动提示、建库建表、复制导出、dump 导入导出、数据库信息、危险操作提示 |
| **文件管理** | 单栏只显示远程；刷新、上传下载、删除/覆盖提示、快速切换目录、历史目录；**和终端无联动** |
| **服务器信息** | CPU / 内存 / 磁盘 / 网络 / 进程探测，终端 Tab 右侧栏，可收成便签 |
| **自动补全** | 命令补全 + SQL 补全，本地和远程都能用，**绝不卡** |
| **操作日志** | 全量记录（连接/命令/SQL/DDL/文件/导入导出），自动脱敏、只存本机；同时是历史、补全、AI 的数据来源 |
| **稳定性** | 一个 Tab 一个进程 |
| **外观** | 统一皮肤（默认 2 套）、字体、快捷键全部可改 |
| **AI** | 只占位留口子 |

### 不做

| 不做 | 理由 |
|---|---|
| MySQL / PG 以外的数据库 | 前期只做这两个 |
| ER 图 / 报表 / 数据同步 / 存储过程调试 | Navicat 的活。（**dump 导入导出要做，见 §9.5**） |
| 独立的 FTP 客户端 | 文件管理是配套能力 |
| 日志分析平台 | 只做"看日志"，不做"分析日志" |
| AI 功能 | V1 只占位 |
| 插件市场 | V1 最多留个接口 |
| 配置云同步（个人版） | 企业版才做 |
| 移动端 / Web 端 | 分散精力 |

## 17. V2 企业版

**企业对数据库和终端连接有限制，可以下发策略和权限、管理端下发配置，
用户不用一个一个配 SSH 和 DB。**

### ① 配置下发（省事）
管理员在管理端配好服务器和数据库，员工登录公司账号，
**连接树里自动出现，一个都不用自己填。** 人走了管理端一撤，权限立刻没了。

### ② 权限限制（管控）
谁能连哪台机器、谁能连哪个库、哪些库只读、哪些危险命令禁止执行 ——
管理端说了算，客户端改不了。

### ③ 操作留痕（合规）
谁什么时候连了哪台机器、执行了什么命令、跑了什么 SQL，管理端能查。

> ✅ **已定：V1 就把操作日志做全（见 §12）**，企业版只是把它上报到管理端。
> 因为它同时也是历史、自动补全、AI 上下文的数据来源，本来就绕不开。

### V1 必须先留好的三个口子
1. **连接来源标记**（本地 / 远程下发）—— 见 §5
2. **每个设置项能显示成「已被公司锁定」**（灰色 + 🔒）。V1 永远不出现，但界面要预留
3. **连接信息和密码分开存** —— 企业版要做到密码不落到员工电脑上
