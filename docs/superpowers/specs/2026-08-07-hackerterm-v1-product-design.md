# HackerTerm 产品需求（大方向）

> 状态：草案，待拍板 · 日期：2026-08-07
> **本文只定大方向。细节见 §6 待议清单，逐条讨论后再展开。**

---

## 1. 一句话

> **终端、数据库、文件管理，都在一个软件里管。每个功能开在自己的 Tab 里。**

就这么简单。

用户今天要装三个软件：终端（Xshell / iTerm2）、数据库（Navicat）、
文件传输（WinSCP / FinalShell）。三套连接配置，三个图标，在三个软件之间找窗口。

HackerTerm 把这三件事收进一个软件。

**不是说不用切换** —— 切 Tab 是正常的，本来就该切。
区别是：切的是同一个软件里的 Tab，不是三个软件的窗口。

---

## 2. 核心机制：左边一棵树，管所有连接

```
┌──────────────────┬───────────────────────────────────────────────┐
│ 🔍 搜索           │▐ web-01 × │▐ orders_db × │▐ zsh × │  +   🤖 │
│                  │  ↑红·生产    ↑红·生产       ↑灰·本地           │
│                  ├───────────────────────────────────────────────┤
│ ▐ 生产环境  ▼     │ [root@web-01 ~]# tail -f app.log              │
│   ● web-01       │                                               │
│   ○ web-02       │                                               │
│   🗄 orders_db    │                                               │
│                  │                                               │
│ ▐ 测试环境  ▼     │                                               │
│   ○ test-01      │                                               │
│   🗄 test_mysql   │                                               │
│                  │                                               │
│ ▐ 本地      ▼     │                                               │
│   🖥 zsh          │                                               │
│   🗄 dev_mysql    │                                               │
└──────────────────┴───────────────────────────────────────────────┘
   ▲ 左边按分组着色              ▲ 顶部 Tab 继承所属分组的颜色
```

树里可以放三种东西：**SSH 连接**、**数据库连接**、**分组**。
两种连接**各自独立创建、独立配置**，谁也不依赖谁。

### 每个功能开在自己的 Tab 里

| 打开的东西 | 开出来是什么 Tab |
|---|---|
| SSH 连接 | 终端 Tab |
| 数据库连接 | 查询 Tab |
| 管理文件 | 文件 Tab |

Tab 可以任意分屏并排看，也可以拖出去成独立窗口。

### 颜色：左边和顶部一致

**分组带颜色，Tab 继承分组的颜色。**

- 生产环境标红 → 侧栏该分组是红的，从它开出来的**所有 Tab 也是红的**
- 一眼看出当前这个 Tab 是不是生产环境，**防止在生产机上误操作**
- 颜色可以按分组设，也可以给单个连接单独指定（覆盖分组颜色）
- 分组可折叠、可拖拽排序、可嵌套

### 右键就是主要入口

| 右键位置 | 菜单 |
|---|---|
| **树的空白处 / 分组上** | 新建 SSH 连接 · 新建数据库连接 · 新建分组 · 设置分组颜色 |
| **一个 SSH 连接** | 打开终端 · **管理文件** · 编辑 · 复制 · 删除 |
| **一个数据库连接** | 打开查询 · 编辑 · 复制 · 删除 |
| **终端窗口里 / 终端 Tab 上** | **管理文件**（开当前这台服务器的文件 Tab） |

**「右键终端 → 管理文件」是最能体现产品价值的一处**：
你正连着 web-01，想看看日志文件，右键就开一个文件 Tab，不用去开 WinSCP。

## 3. V1 做什么

| 模块 | 做什么 |
|---|---|
| **终端** | 本地 Shell + SSH，多标签、分屏、主题、快捷键 |
| **连接树** | 统一管理 SSH 和数据库连接，分组、颜色标记、搜索、右键操作；支持从 Xshell / FinalShell / PuTTY 导入 |
| **数据库** | 查询、改数据、看表结构 |
| **文件管理** | 上传下载、直接改远程文件；可从连接右键开，也可从终端右键开 |
| **AI** | 看得见终端和数据库，能解释报错、生成命令和 SQL |
| **自动补全** | 命令补全 + SQL 补全，本地和远程都能用 |
| **稳定性** | 界面崩了会话不断；一个面板出问题不影响别的 |
| **外观** | 换肤、字体、快捷键全部可改 |

## 4. V2 企业版做什么

用你的原话：**企业对数据库和终端连接有限制，可以下发策略和权限、
管理端下发配置，用户不用一个一个配 SSH 和 DB。**

拆成三件事：

### ① 配置下发（省事）
管理员在管理端配好服务器和数据库，员工装上客户端登录公司账号，
**连接树里自动出现，一个都不用自己填。**
新人入职当天能干活，人走了管理端一撤，权限立刻没了。

### ② 权限限制（管控）
谁能连哪台机器、谁能连哪个库、哪些库只读不能写、
哪些危险命令禁止执行 —— 管理端说了算，客户端改不了。

### ③ 操作留痕（合规）
谁在什么时候连了哪台机器、执行了什么命令、跑了什么 SQL，管理端能查。

> ⚠️ 第 ③ 条是我加的，你没提。加的理由是企业敢把生产环境交给一个工具，
> 通常要能查得到操作记录。**但如果你的客户不看重，可以砍掉** ——
> 这条影响 V1 要不要提前埋点，需要你明确。

### V1 现在必须先留好的两个口子

1. **每个设置项要能显示成「已被公司锁定」**（灰色 + 🔒）。V1 永远不出现这个状态，但界面要预留。
2. **连接信息和密码分开存。** 企业版要做到密码不落到员工电脑上，
   V1 如果混在一起，V2 就得重做。

## 5. 明确不做

| 不做 | 理由 |
|---|---|
| 大而全的数据库工具（ER 图、报表、数据同步、备份） | Navicat 的活，比不过也不需要比 |
| 支持几十种数据库 | DBeaver 支持 80+ 种，广度赛道已死 |
| 独立的 FTP 客户端 | 文件管理是配套能力，不是独立产品 |
| 日志分析平台 | 只做"看日志"，不做"分析日志" |
| 插件市场 | V1 最多留个接口 |
| 配置云同步（个人版） | 要账号体系和服务端，是独立项目；企业版才做 |
| 移动端 / Web 端 | 分散精力 |

## 6. 待议清单

**大方向定了之后逐条讨论，现在不展开。**
你判断哪些该做、哪些不做、哪些放 V2，我再逐条写细节。

### 确定要做，细节待定
| # | 议题 | 需要决定什么 |
|---|---|---|
| 1 | **连接树 + 右键菜单** | 树怎么组织、右键放哪几项、拖拽排序要不要 |
| 1b | **Tab 管理** | Tab 怎么分屏、能不能拖出成独立窗口、Tab 太多时怎么办、关闭时要不要确认 |
| 1c | **颜色体系** | 预设几种颜色、Tab 上颜色显示成什么样（左边一条竖线 / 整个标题染色 / 底部一条线） |
| 2 | **连接配置** | SSH 和 DB 各有哪些字段、跳板和隧道怎么配、导入支持哪几种 |
| 3 | **终端** | 分屏方式、回滚、搜索、复制粘贴行为 |
| 4 | **数据库** | V1 支持哪几种（我建议 MySQL + PostgreSQL）、能不能改数据、写操作怎么防误 |
| 5 | **文件管理** | 双栏还是单栏、能不能直接编辑远程文件、要不要和终端目录联动 |
| 6 | **AI** | 几个入口、能看到什么、能不能自己执行命令 |
| 7 | **自动补全** | 补全内容从哪来、弹窗还是行内、远程怎么补 |
| 8 | **快捷键** | 默认键位、要不要抢 shell 的键（尤其 `Ctrl+R`） |
| 9 | **皮肤** | 换肤范围、内置几套、能不能导入 iTerm2 配色 |
| 10 | **稳定性** | 对用户承诺到什么程度 |
| 11 | **历史** | 命令历史和 SQL 历史怎么做、要不要跨主机搜索 |

### 还不确定要不要做
| # | 议题 | 我的初步意见 |
|---|---|---|
| 12 | **日志面板** | 想做（多机日志合并是运维刚需），但可推到 1.0 之后 |
| 13 | **数据库可选择走某个 SSH 连接做隧道** | 建议做，是个顺手的便利，但不是核心卖点 |
| 14 | **生产环境标红 + 危险命令拦截** | 想做，成本低，运维会喜欢 |
| 15 | **插件接口** | V1 可以整个推后 |
| 16 | **三平台同时发** | 建议先发两个，第三个跟上 |
