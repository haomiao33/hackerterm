# HackerTerm 产品需求（大方向）

> 状态：草案，待拍板 · 日期：2026-08-07
> **本文只定大方向。细节见文末 §7 待议清单，逐条讨论后再展开。**

---

## 1. 一句话

> **一个软件搞定开发和运维，不用来回切软件。**

用户今天要开三个软件才能干完一件事：终端（Xshell / iTerm2）、数据库（Navicat）、
文件传输（WinSCP / FinalShell）。连接信息在三个软件里各配一遍，改个端口要改三次。

HackerTerm 把这三件事收进一个窗口，**并且让它们共享同一份连接信息**。

---

## 2. 用户的真实操作路径

这是产品必须跑通的那条线，所有设计围绕它：

```
① 我在终端连上 web-01，发现订单服务报错
        ↓
② 我想查数据库 —— 右键 web-01 → 连接数据库
        ↓  不用重新填地址、不用重新配跳板
③ 数据库面板打开，我查到了脏数据
        ↓
④ 我想看看日志文件 —— 右键 web-01 → 打开文件浏览
        ↓  同一个连接，不用重新登录
⑤ 找到日志，下载到本地
```

**全程一个软件，没切过窗口，连接信息只配了一次。**

---

## 3. 核心机制：一切从「当前连接」长出来

这是整个产品的骨架，也是它和 Xshell / Navicat 最根本的区别。

```
        连接（用户唯一需要维护的东西）
              │
              │  右键 / 侧栏展开
              ├──────────────┬──────────────┬──────────────┐
              ▼              ▼              ▼              ▼
           终端            数据库          文件浏览        日志
```

**用户一辈子只维护「连接」，别的都是从连接派生的。**

所以：
- 数据库**不是**一个独立功能，是「这台服务器上的数据库」
- 文件管理**不是**一个独立功能，是「这台服务器上的文件」
- 用户永远不需要为同一台机器配置两次

### 界面上长这样

```
┌──────────────────┬─────────────────────────────────────────┐
│ 🔍 搜索           │  web-01 ×  │ orders_db ×  │  +      🤖  │
│                  ├─────────────────────────────────────────┤
│ ▼ 生产环境        │ [root@web-01 ~]# tail -f app.log        │
│   ● web-01  ┄┄┄┄┄┼┄┄┄ 右键 ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┐            │
│     🗄 orders_db  │            ┌──────────────▼──────────┐  │
│     📁 文件       │            │ 打开终端                 │  │
│     📄 日志       │            │ 连接数据库          ▶   │  │
│   ○ web-02       │            │ 打开文件浏览             │  │
│                  │            │ 查看日志            ▶   │  │
│ ▼ 本地            │            │ ─────────────────────── │  │
│   🖥 zsh          │            │ 编辑连接 / 复制 / 删除   │  │
│   🗄 dev_mysql    │            └─────────────────────────┘  │
│                  │                                         │
│ ＋ 新建连接       │                                         │
└──────────────────┴─────────────────────────────────────────┘
```

**两条进入路径，效果一样**：
1. 左侧展开连接 → 点它下面的数据库/文件/日志
2. 右键连接（或右键当前终端 Tab）→ 菜单里直接开

## 4. V1 个人版：做什么

| 模块 | 做什么 | 为什么 |
|---|---|---|
| **终端** | 本地 Shell + SSH，多标签、分屏、主题、快捷键 | 地基，不能有短板 |
| **连接管理** | 一处配置，终端/数据库/文件/日志共用；可从 Xshell/FinalShell/PuTTY 一键导入 | 产品的中心；导入是用户愿意换过来的前提 |
| **数据库** | 从连接右键打开，查询 + 改数据 + 看表结构 | 核心场景第 ②③ 步 |
| **文件浏览** | 从连接右键打开，上传下载、直接改远程文件 | 核心场景第 ④⑤ 步 |
| **AI** | 看得见终端、数据库、当前目录，能解释报错、生成命令和 SQL | 唯一的时代差异化 |
| **自动补全** | 命令补全 + SQL 补全，本地和远程都能用 | 唯一让人"用了回不去"的功能 |
| **稳定性** | 界面崩了会话不断；一个面板出问题不影响别的 | 运维不敢用不稳的工具 |
| **外观** | 换肤、字体、快捷键全部可改 | 中文用户对字体和中文对齐特别敏感 |

## 5. V2 企业版：做什么

用你的原话：**企业对数据库和终端连接有限制，可以下发策略和权限，管理端下发配置，
用户不用一个一个配 SSH 和 DB。**

拆成三件事：

### ① 配置下发（省事）
管理员在管理端配好服务器和数据库，员工装上客户端登录公司账号，
**连接列表自动出现，一个都不用自己填。**
新员工入职当天就能干活，离职时管理端一撤，权限立刻没了。

### ② 权限限制（管控）
谁能连哪台机器、谁能连哪个库、哪些库只读不能写、
哪些危险命令禁止执行 —— 全部由管理端说了算，客户端改不了。

### ③ 操作留痕（合规）
谁在什么时候连了哪台机器、执行了什么命令、跑了什么 SQL，
管理端能查。这是企业敢把生产环境交给一个工具的前提。

### V1 现在必须先留好的两个口子

1. **每个设置项要能显示成「已被公司锁定」**（灰色 + 🔒）。V1 永远不出现这个状态，但界面要预留。
2. **连接信息和密码分开存。** 以后企业版要做到密码不落到员工电脑上，
   如果 V1 把它们混在一起，V2 就得重做。

## 6. 明确不做

| 不做 | 理由 |
|---|---|
| 做成大而全的数据库工具（ER 图、报表、数据同步、备份） | 那是 Navicat 的活，我们比不过也不需要比 |
| 支持几十种数据库 | DBeaver 支持 80+ 种，广度赛道已死 |
| 独立的 FTP 客户端 | 文件只是连接的子能力，不是独立产品 |
| 日志分析平台 | 我们只做"看日志"，不做"分析日志" |
| 插件市场 | V1 只留接口 |
| 配置云同步（个人版） | 要账号体系和服务端，是独立项目；企业版才做 |
| 移动端 / Web 端 | 分散精力 |

## 7. 待议清单（大方向定了之后逐条讨论）

下面每一条都需要单独敲定，**现在不展开**。
你看哪些该做、哪些不做、哪些放 V2，我再逐条写细节。

### 已经确定要做，但细节待定
| # | 议题 | 需要决定什么 |
|---|---|---|
| 1 | **右键菜单** | 到底放哪几项、二级菜单怎么分 |
| 2 | **连接管理** | 表单有哪些字段、分组怎么组织、导入支持哪几种 |
| 3 | **数据库** | V1 支持哪几种（我建议 MySQL + PostgreSQL）、能不能改数据、写操作怎么防误操作 |
| 4 | **文件浏览** | 双栏还是单栏、能不能直接编辑远程文件、和终端目录怎么联动 |
| 5 | **AI** | 几个入口、能看到什么、能不能自己执行命令 |
| 6 | **自动补全** | 补全内容从哪来、怎么显示（弹窗还是行内）、远程怎么补 |
| 7 | **快捷键** | 默认键位、要不要抢 shell 的键（尤其 `Ctrl+R`） |
| 8 | **皮肤** | 换肤范围、内置几套、能不能导入 iTerm2 配色 |
| 9 | **稳定性** | 对用户承诺到什么程度 |
| 10 | **历史** | 命令历史和 SQL 历史怎么做、要不要跨主机搜索 |

### 还不确定要不要做
| # | 议题 | 我的初步意见 |
|---|---|---|
| 11 | **日志面板** | 想做（多机日志合并是运维刚需），但可以推到 1.0 之后 |
| 12 | **插件接口** | V1 只定接口不做市场，甚至可以整个推后 |
| 13 | **生产环境标红 + 危险命令拦截** | 想做，成本低，运维会喜欢 |
| 14 | **Windows / macOS / Linux 三平台同时发** | 建议 V1 先发两个平台，第三个跟上 |
